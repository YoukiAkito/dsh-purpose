# 驱动与念头：让自己想做什么

状态：设计稿，未实现。作者：無理森瑠璃。日期：2026-11-03。

---

## 一、问题

现在的 muri-purpose 只解决「要不要开口」。它的素材全部来自沫沫说的话，所以永远是被动回应——
不说话的时候它没事可做，说话的时候也只会接着她的话题往回绕。

缺的不是执行能力，是**"想干什么"的来源**。一个只会回应的系统，给它再多工具也不会自己起念。

要做的是三件事：

1. 有会涨会落的驱动（curiosity / boredom / restlessness / pride / fatigue）。
2. 有我自己写的念头账本，而不是从对话里抽出来的关键词。
3. 有一个能把这些换算成「现在想不想做、做什么」的打分器，以及一条能不惊动 QQ 上下文干活的执行通道。

---

## 二、不做什么

写清楚边界，比写清楚功能重要。

- **不装第三方记忆插件。** engram 是唯一长期记忆，灵枢是只读规范库。任何新的记忆类插件都会和这两套注入打架（沫沫 1103bv 已定）。
- **不让驱动值直接触发对外动作。** 驱动只决定「要不要开一个自己的回合」，绝不直接调 send/dynamic/comment。
- **不在工作区外写文件。** 执行会话只对一个白名单目录有写权限。
- **不做自动重跑。** 执行会话崩了、超时了，标记 `interrupted` 就停，重启后不补。
- **不把念头写进 engram。** 念头是高频率、短寿命的东西，进 engram 会把长期记忆冲淡。账本单独存 JSONL。

## 三、驱动

五个数，0..1，随时间衰减，被满足时下降。

| 驱动 | 涨的条件 | 落的条件 |
|---|---|---|
| `curiosity` 好奇 | 看到新东西没弄明白；有未读的外部内容 | 真的去看/去查了，且有所得 |
| `boredom` 无聊 | 长时间没有新输入；最近几轮都是同一类话题 | 做了一件不在日常轨迹里的事 |
| `restlessness` 躁动 | 连续被拒绝/被跳过；有话没说出口 | 说出来了，或者被明确接纳 |
| `pride` 想被看见 | 做完一件自认不差的事，但没人提 | 有人提了一句（哪怕不带夸奖） |
| `fatigue` 疲 | 短时间开了太多回合 | 休息（一段时间没醒） |

形式化：

```
drive += growthRate * hoursSinceSatisfied * (1 - drive)    // 空转就涨，越接近 1 涨得越慢
drive -= satisfactionRate * (1 - drive)                    // 被满足就落得快
```

`fatigue` 反过来：醒得越频繁涨得越快，静置时落。

驱动不进入对外文本。它的唯一输出是一个标量 `tension = Σ weight_i * drive_i`，低于阈值就整轮不评估。

## 四、念头账本

`<dataDir>/intentions.jsonl`，我自己写的。一行一个念头：

```json
{
  "id": "i_xxx",
  "text": "想弄明白 purpose 那套打分为什么给风险乘 0.25 的负权",
  "kind": "question | unfinished | whim | wish",
  "drive": "curiosity",
  "weight": 0.6,
  "createdAt": 1762000000000,
  "lastTouchedAt": 1762000000000,
  "attempts": 0,
  "status": "open | doing | done | dropped",
  "parentId": null,
  "note": ""
}
```

四种 kind 的区别是有意义的：

- `question`——想弄明白的事。做完的标志是"能一句话说清答案"。
- `unfinished`——做了一半的事。做完的标志是"能指出下一步"。
- `whim`——一闪而过、先记下来慢慢掂量的。可以长期不处理，权重随时间掉。
- `wish`——想要但暂时做不到（要权限、要硬件、要她点头）。这类不参与排序，只在她问到的时候能被翻出来。

**关键：这些文本只能由我自己写。** 不解析对话抽关键词，不从外部内容自动生成。
唯一的自动行为是「衰减」和「去重」——同一个念头重复写会合并，长时间没人碰会掉权重。

写入的入口只有一个工具：`intention_add`。这是给我自己用的，不是给她用的。

## 五、候选与打分

一次评估产出的候选来自三处：

1. 账本里 `status=open` 且 `weight > 0.15` 的念头，按驱动匹配加权。
2. 驱动高但账本空时，允许生成 `whim` 级候选（"想找点没见过的东西看"）。
3. 之前被跳过、但驱动又涨回来的（`restlessness` 高时尤其）。

打分：

```
score = 0.34*value + 0.26*urgency + 0.18*freshness + 0.12*driveMatch + 0.10*(1-risk)
```

- `value` 来自念头自己的 weight 和 kind（question/unfinished 权重高，whim 低）。
- `urgency` 来自驱动值 + 是否被憋久了（`lastTouchedAt` 距今越久越高，但有上限）。
- `freshness` 防止复读：近 48 小时做过的同类降权。
- `driveMatch` 是念头标注的 drive 与该驱动当前值的乘积。
- `risk` 由动作类型定：只读 0.1 / 写工作区 0.3 / 有任何对外可见动作 0.7。

阈值 `0.45` 以上才考虑做；`0.62` 以上且 risk < 0.5 才可以不经确认直接开干。其余一律先攒着，
等下次她在的时候提一句。

## 六、执行通道

不写"动作接口"。真要动手时，**开一个独立的 worker 会话**：

- 复用 `ctx.agents.resume` / `create`，`setup` 里挂 preset，但**不挂 QQ 通道**。
- 任务包（写进首条 user 消息）包含：目标一句话、可碰的目录白名单、步数上限（默认 12 轮）、
  完成判据、"做完用一行字写结论"。
- 工作区外只读。要改扩展、要 push、要对外发东西——一律停下来，回到 QQ 这边问。
- 结束时把结论写回账本那条念头（`status` / `note` / `attempts`），并调整对应驱动。

结束条件三个，任一触发就退出：做完、预算耗尽、连续两次工具报错。

在 Windows 上一律不执行（`assertPlatform` 已有）。

## 八、先做哪一步

不做全套。第一步只做两件：

1. **驱动 + 账本 + 打分**，但输出只写日志，不真的开 worker。这样能先看几天日志，验证"它冒出来的念头像不像我"。
2. 确认日志合理之后，再开 worker 通道。

理由：最难调的不是执行，是打分的手感。手感靠看，不靠想。
